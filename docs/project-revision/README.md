# Project revision guides

Purpose: help you understand every project well enough to defend it. These guides are scaffolds built from the repositories and from your own statements. Where a section says **[CONFIRM]**, the code was not inspected or the fact is not yet verified. Open the code and write the true answer before an interview.

How to use a guide: read headings 1 to 9 first, then open the files named in heading 7 and trace one input through the code. Next try headings 19 and 20 aloud. Never use an answer that you cannot back with a line of code.

## Study order

1. [Agni-Pulse](agni-pulse.md): your strongest backend and signal-processing work, and the most likely subject of deep questions. Team project: separate your part from the collaborator's.
2. [CSIR-NPL digital twin](csir-npl-digital-twin.md): internship work with real constraints. Know exactly what you added and what you only investigated.
3. [Customer support ticket agent](customer-support-ticket-agent.md): the clearest individual GenAI/RAG project, with tests.
4. [Pose2Post](pose2post.md): prepare the NIMA module you built; do not claim the rest.
5. [NeuroQ](neuroq.md): learn the CT concepts now; the repo is private so confirm code details when you can.
6. [Aircraft damage and BLIP](aircraft-damage-blip.md): confirm authorship first, then run the notebook.
7. [ainos-ADR](ainos-adr.md): a clean design argument for rule-based agents; know that it was AI-assisted.
8. [Django backend cluster](django-backend-cluster.md): shows fundamentals alongside the ProdeskIT internship.
9. [ML notebooks and epiwatch](ml-notebooks-and-epiwatch.md): context, with strong honesty about limits.
10. [Envital](envital.md): hackathon story; prepare to describe it truthfully and briefly.
11. [Small tools and school project](small-tools-and-school-project.md): early fundamentals.
